1. Sign in

Gets a JWT from POST /auth/login or /auth/register and sends it as Authorization: Bearer … on every booking call.

2. Book a booth

Clicking Book again with the same key is a retry: the server replays the first result (marked Idempotent-Replayed). Change the body but keep the key and it is rejected.

3. Race for one date

Fires every request at once for the same booth and date. Different keys: expect one 201 and the rest 409. Same key: expect all 201, one created and the rest replays. Browsers open at most 6 connections per site, so the npm run demo:concurrency script is the stronger proof.
